# 开发大纲

原生版与网页版并行。网页版照旧是正式版，原生版一块一块追上来。
每一阶段结束时都是一个能交给测试用户的版本。

排序的原则：
1. 先做「每天都用」的，后做「偶尔打开」的；
2. 先做不花钱、不出错就不会坏事的，再做会自动调接口的；
3. 每一块都带自动测试；会调接口的，先写「接口一直失败时打出去几次」的测试。

---

## 阶段 0：底层与骨架（已完成）

- 本地库：装下网页版全部数据域，不认得的字段原样留着
- 导入网页版备份：ZIP、纯数据、加密，失败不动已有数据
- 接口层：Anthropic 与 OpenAI 兼容，流式，重试与换接口默认关，每次请求记账
- 提示词：模板由脚本从网页版生成；一对一聊天按网页版默认布局拼装
- 回复解析：标记正则照抄网页版
- 界面：消息列表、一对一聊天、接口设置、用量与上限、问题反馈
- 问题反馈：诊断记录与导出，不含聊天内容与密钥
- 自动测试，推送即编译（到 2026-10-13 共 69 项）

## 阶段 2：聊天补齐

目标：网页版聊天里常用的能力，原生版都有。

| 项 | 内容 | 花钱 |
|---|---|---|
| 预设与提示词 | 「设定集」：预设切换、条目排序、添加条目；锁定段只读 | 否 |
| 表情库 | 管理、分组、导入 | 否 |
| 互动能力 | 转账、礼物、外卖、位置、约定、拍一拍、回应、备注、心愿；落成网页版同样的消息与状态 | 否（不另调接口） |
| 心声、旁白、翻译 | 行内与单独显示 | 单独生成心声、单独翻译会多调一次，默认关 |
| 生图 | 接图片接口；角色发图时生成 | 是，默认关 |
| 语音 | 朗读（TTS）、听写（ASR）、语音消息 | 是，默认关 |
| 群聊 | 多个角色、发言人、@、群管理 | 否 |
| 记忆整理 | 自动提取、关系底色、历史压缩 | 是，默认关；先记「试过」再发 |
| 主动消息 | 角色在设定的间隔内主动发起对话 | 是，默认关 |
| 通话 | 语音通话 | 是 |

**主动消息接后台消息服务器（用户定的，2026-10-13），放在阶段 2 的最后做。**
iOS 不让 app 在后台长时间跑，app 关着时没法自己定时调接口。网页版用「后台消息服务器」（`worker/push.js`）：
服务器到点调接口，再推送通知。原生版接同一个服务器，交接规矩照网页版 ARCHITECTURE 4.242：
同一次开口只能扣一次钱，退到后台归服务器，回到前台先取回服务器的结果再恢复本机发。
